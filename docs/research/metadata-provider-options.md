# Game metadata and box-art provider options

Research date: 2026-08-05
Decision ticket: [#7, Evaluate game metadata and box-art providers](https://github.com/Mill1893/rom-manager/issues/7)

## Scope and legal framing

This report compares provider interfaces that could support automatic ROM matching and artwork download in a distributable, MIT-licensed, local-first desktop application. It does **not** select a provider policy. It distinguishes three rights that are easy to conflate:

1. A license for ROM Manager's source code.
2. Permission to call a provider's service.
3. Permission to cache, display, package, or redistribute the returned metadata and images.

An MIT license for the application grants no rights in third-party metadata or game artwork. Likewise, an open-source API implementation does not necessarily license the database or images served by it. Where provider-owned material reviewed for this report does not expressly settle commercial use, caching, attribution, or redistribution, the table says **unresolved** rather than inferring permission.

Only provider-owned documentation, terms, schemas, websites, and official repositories are used below.

## Provider details

### IGDB

**Capabilities.** IGDB's schema exposes games, platforms, releases, alternative/international names, covers, artwork, and screenshots. Search is available for games and platforms. The `external_games` endpoint is described as "Game IDs on other services" and currently lists sources such as Steam, GOG, Microsoft, Android, Amazon ASIN, Epic, Xbox Marketplace, and PlayStation Store. That is useful for catalog reconciliation, but it is not a ROM-identity interface: the documented object `checksum` is the UUID checksum of the **API object**, not a cartridge/disc content hash. No ROM CRC, MD5, SHA-1, serial, or No-Intro lookup endpoint appears in the official schema. [Getting started and search](https://api-docs.igdb.com/#getting-started), [alternative names](https://api-docs.igdb.com/#alternative-name), [external games](https://api-docs.igdb.com/#external-game), [platforms](https://api-docs.igdb.com/#platform)

**Artwork.** `cover`, `artworks`, and `screenshots` are separate resources with image IDs, dimensions, and URLs. The image reference supports size variants. IGDB warns that replaced/removed images remain available for 30 days, which is an operational warning for cache invalidation, not a grant of perpetual cache rights. [Covers](https://api-docs.igdb.com/#cover), [artwork](https://api-docs.igdb.com/#artwork), [screenshots](https://api-docs.igdb.com/#screenshot), [images](https://api-docs.igdb.com/#images)

**Authentication and desktop fit.** Setup requires a Twitch account, 2FA, and registration of a confidential application to generate a client secret. IGDB then requires the client-credentials flow. Twitch describes client credentials as server-to-server and for clients that can securely store a secret. A distributable local desktop binary cannot keep a shared client secret confidential, so practical options would need provider approval, a project-operated broker, or bring-your-own Twitch application credentials; each changes the local-first/user-setup model. This report does not choose among them. [IGDB account creation/authentication](https://api-docs.igdb.com/#account-creation), [Twitch client-credentials flow](https://dev.twitch.tv/docs/authentication/getting-tokens-oauth/#client-credentials-grant-flow)

**Limits, cost, and legal status.** IGDB publishes 4 requests per second and at most 8 open requests. Its docs say the API is free for **non-commercial** use under the Twitch Developer Services Agreement and direct commercial projects to its partner program. Daily CSV dumps are exclusive to data partners. The documentation license section applies the Twitch agreement to code samples; it does not state that API data or artwork is open content. The public materials reviewed do not give a commercial price, attribution rule, or clear local-retention/redistribution license. These points require written commercial/redistribution terms before treating IGDB content as distributable application data. [Rate limits](https://api-docs.igdb.com/#rate-limits), [partnership and dumps](https://api-docs.igdb.com/#partnership), [documentation license](https://api-docs.igdb.com/#license), [Twitch Developer Services Agreement](https://www.twitch.tv/p/legal/developer-agreement/)

### ScreenScraper

**Capabilities.** The official API says it exposes all ScreenScraper data and media in XML, JSON, or INI. `jeuInfos.php` accepts a system ID plus ROM filename, size, CRC, MD5, and SHA-1, while `jeuRecherche.php` searches by name and returns up to 30 games ordered by probability. Game responses include ROM associations and region/language-specific records. The live provider site lists a particularly deep set of retro systems, including arcade boards, consoles, handhelds, computers, hacks, and virtual systems. This is the most ROM-specific interface examined, but coverage and match quality still need empirical testing with the application's target corpus. [Official WebAPI v2 documentation](https://www.screenscraper.fr/webapi2.php?alpha=0&devid=xxx&devpassword=yyy&softname=zzz&output=xml&ssid=aaa&sspassword=bbb), [live platform catalog](https://www.screenscraper.fr/)

**Artwork.** The schema advertises game and system media-list endpoints and image/video/manual downloads. Media records expose format, region, support/version behavior, and file hashes; game data includes common media such as 2D/3D box art, screenshots, title screens, wheels/logos, fan art, videos, and manuals where present. Image endpoints support maximum dimensions and PNG/JPEG output. [Media-list and game-media sections](https://www.screenscraper.fr/webapi2.php?alpha=0&devid=xxx&devpassword=yyy&softname=zzz&output=xml&ssid=aaa&sspassword=bbb)

**Authentication, limits, and availability.** A software developer must contact ScreenScraper through its forum, present the software, and obtain a developer ID/password. Requests may also carry the end user's ScreenScraper username/password. `ssuserInfos.php` returns allowed threads, download speed, requests today, failed requests today, per-minute/day maxima, and failed-match maximum. The documentation says quotas depend on contribution/financial-support level and that quota handling by scraper software is mandatory. Its error contract shows that service load can close non-member access and that total closure, concurrency, daily, and failed-match limits are expected conditions. [API eligibility, credentials, quota, and errors](https://www.screenscraper.fr/webapi2.php?alpha=0&devid=xxx&devpassword=yyy&softname=zzz&output=xml&ssid=aaa&sspassword=bbb)

**Legal status.** The controlling statement is unusually direct but incomplete:

> "L'API ScreenScraper ne peut être intégré que dans les applications entièrement gratuites et distribuées, ou, dans le cas contraire, avec l'autorisation préalable et les conditions dictées par l'équipe de ScreenScraper."

In context, integration is allowed only in entirely free, distributed applications, otherwise prior authorization and ScreenScraper's conditions are required. Whether an MIT application that may be sold by downstream distributors is "entirely free," whether donations are acceptable, whether developer credentials may be shipped, and what cache/attribution/redistribution rules apply are not answered in the reviewed docs. Those are written-approval questions, not safe assumptions. API v2 is also labeled beta and subject to change without notice. [Official WebAPI v2 introduction](https://www.screenscraper.fr/webapi2.php?alpha=0&devid=xxx&devpassword=yyy&softname=zzz&output=xml&ssid=aaa&sspassword=bbb)

### SteamGridDB

**Capabilities and artwork.** The official OpenAPI 3.1 schema provides name autocomplete, SteamGridDB game IDs, and selected external-platform IDs. Its external platform enum is storefront-oriented (`steam`, `origin`, `egs`, `bnet`, `uplay`, `flashpoint`, `eshop`), so ROM matching would generally be filename/title plus platform, with ambiguity handling elsewhere. Asset endpoints provide grids, heroes, logos, and icons, including static/animated, style, dimensions, MIME type, and content-safety filters. Grid dimensions include vertical formats such as 600x900, but community "alternate," "blurred," and "no logo" styles mean a grid cannot automatically be treated as original box art. [Official OpenAPI schema](https://www.steamgriddb.com/static/openapi.yml), [API reference](https://www.steamgriddb.com/api/v2)

**Authentication and limits.** The schema directs a user to generate an API key in profile preferences and send it as an `Authorization: Bearer` token. That supports a bring-your-own-key desktop flow without a project-wide embedded secret. No numeric request quota, response quota headers, service-level commitment, or API pricing is stated in the schema or FAQ reviewed; an implementation would have to handle 429/availability conservatively and seek confirmation before setting product assumptions. [OpenAPI authentication definition](https://www.steamgriddb.com/static/openapi.yml), [profile preferences](https://www.steamgriddb.com/profile/preferences)

**Legal status.** The terms define the service as searching, downloading, and uploading game images, then restrict access to "personal, non-commercial use" and prohibit distributing any part of the service without explicit written permission. Uploaders grant each service user rights to access/use/reproduce/distribute their user content only "to the extent permitted by the Service and under these Terms of Use." The FAQ separately says assets "may be used anywhere you can imagine from custom front-ends" but does not override the terms' commercial and distribution restrictions. The terms also recognize third-party rights and require uploaders to own or have permission, which is a submission warranty rather than a guarantee that every game image is cleared. Commercial distribution, long-lived caching, mirroring, and attribution should therefore be treated as unresolved pending written permission. [Terms of Use](https://www.steamgriddb.com/terms), [FAQ](https://www.steamgriddb.com/faq), [official API schema](https://www.steamgriddb.com/static/openapi.yml)

### TheGamesDB

**Capabilities.** The current official Swagger 2.0 schema exposes game lookup by internal ID, name, platform, unique/external ID, and ROM hash, with platform/region/country filters. The hash route accepts a hash string and optional type such as MD5 or CRC. The schema does not document hash normalization, header stripping, accepted hash-type vocabulary beyond examples, or corpus completeness, so these need live-key validation. The platform browser shows both classic and current platforms. [Official API schema](https://api.thegamesdb.net/spec.yaml), [platform browser](https://thegamesdb.net/list_platforms.php)

**Artwork.** `Games/Images` supports `fanart`, `banner`, `boxart`, `screenshot`, `clearlogo`, and `titlescreen`; box art records can distinguish front/back. Responses provide original, small, thumbnail, cropped, medium, and large CDN bases. Platform image endpoints are also present. [Games image endpoint and models](https://api.thegamesdb.net/spec.yaml)

**Authentication, quota, and cost.** Every data route takes an API key. The official key page says the user must be logged in to view it. API responses include `remaining_monthly_allowance`, `extra_allowance`, and `allowance_refresh_timer`, and `/v1/API/Limit` checks allowance without consuming it. The schema's numeric values are examples, not a statement of the default quota. An increase page requires site login. The linked official Patreon currently lists $1, $5, and $15 monthly tiers, but its public tier page does not map those payments to API allowance, so no cost-per-request conclusion is supportable. [API key page](https://api.thegamesdb.net/key.php), [API allowance schema](https://api.thegamesdb.net/spec.yaml), [limit-increase page](https://thegamesdb.net/increase_usage.php), [official Patreon tiers](https://www.patreon.com/thegamesdb/membership)

**Legal status and maintenance.** The schema labels the API GPL-3.0 and links API implementation source; the current official Website repository also carries GPL-3.0. GPL covers that software, not automatically the database rows, user-supplied descriptions, or copyrighted game artwork returned by the service. The official site/schema/repository materials reviewed expose no separate content terms granting commercial reuse, cache duration, attribution, bulk redistribution, or image sublicensing. Those rights need direct clarification. The official repository is active and contains the website and API schema/implementation, reducing technical abandonment risk while leaving content-license risk high. [Schema license declaration](https://api.thegamesdb.net/spec.yaml), [official repository](https://github.com/TheGamesDB2/Website), [repository GPL-3.0 license](https://github.com/TheGamesDB2/Website/blob/main/LICENSE)

### libretro thumbnails

**Capabilities and local-first fit.** The official umbrella repository organizes separate repositories by console/system. Its required path is `Playlist Name/Named_Type/Game Name.png`, and RetroArch's documentation describes normalized label-based matching and on-demand server downloads. The four asset classes are `Named_Boxarts`, `Named_Logos`, `Named_Snaps`, and `Named_Titles`. This can work as an offline, name-addressed artwork index once ROM Manager has a canonical platform and game label, but it does not itself provide rich metadata or an authenticated fuzzy-search/hash API. [Official repository README](https://github.com/libretro-thumbnails/libretro-thumbnails), [RetroArch playlist/thumbnail documentation](https://docs.libretro.com/guides/roms-playlists-thumbnails/)

**Distribution and provenance.** The repository has no declared license. Its own credits say files have many sources, including MobyGames, Fandom, and volunteer contributions, and that game/promotional art originates from each game's developers and publishers. Submission rules and public availability do not substitute for an express license. Downloading images for a user's private local library and redistributing a bundled/mirrored corpus are legally different; the latter is not supported by an express grant in the reviewed materials. [README credits and guidelines](https://github.com/libretro-thumbnails/libretro-thumbnails), [repository metadata showing no license](https://api.github.com/repos/libretro-thumbnails/libretro-thumbnails)

**Operations.** The project documents Git/submodule installation and a public thumbnail server. Repository updates are exported about every two days, while accepted changes may take one to two weeks to become visible. There is no provider-published API quota or service guarantee. A client should not clone the full multi-system image corpus by default; apart from legal uncertainty, that conflicts with a lightweight local-first distribution. [Technical usage and thumbnail-server section](https://github.com/libretro-thumbnails/libretro-thumbnails#technical-usage-and-maintenance-of-this-repository)

## Cross-provider findings for later policy work

- **Identity and presentation are separate seams.** ScreenScraper and TheGamesDB document ROM hash/serial-aware paths. IGDB and SteamGridDB are chiefly catalog/title/store-ID systems; libretro thumbnails are chiefly a label-addressed image corpus. A provider abstraction should not assume one service must perform both identity resolution and artwork selection.
- **A local cache needs provider-specific provenance.** Store provider name, provider object/asset ID, source URL, retrieval time, selected region/language, and any provider attribution alongside cached data. This makes expiration, replacement, deletion, and provider removal possible without pretending all cached records share one license.
- **Shared secrets are incompatible with an untrusted desktop binary.** IGDB explicitly requires a confidential client and ScreenScraper issues developer credentials after approving software. SteamGridDB and TheGamesDB support end-user API keys. Any future policy must decide separately whether to operate a broker, require bring-your-own credentials, or omit a provider.
- **No reviewed source licenses all returned box art for unrestricted MIT-style redistribution.** SteamGridDB's terms are personal/non-commercial; ScreenScraper limits eligible applications; IGDB reserves commercial use for partnership; TheGamesDB does not publish a content license in the reviewed materials; libretro declares no repository license.
- **"Free API" is not the same as distributable product rights.** Provider cost, app monetization, downstream resale allowed by MIT, local caching, and shipping a pre-populated artwork database are separate questions.

## Questions requiring provider confirmation or counsel

1. Does "entirely free" in ScreenScraper's API rule include MIT software that a downstream party may sell, and may approved developer credentials be embedded in distributed binaries?
2. For each API provider, may an end user retain metadata and images indefinitely for personal offline use? Must removed/replaced assets be deleted, and on what schedule?
3. Does any provider permit the project to ship a shared cache, mirror, fixture subset, or pre-populated database? If so, under what attribution and takedown process?
4. Do commercial-use restrictions apply to a free application that accepts donations, is distributed through a paid store, or is bundled with paid hardware?
5. For TheGamesDB, what license governs API data and each image class, and what baseline/increased allowances apply to a desktop application?
6. For SteamGridDB, does API use by a freely distributed desktop front end require written permission despite the FAQ's custom-front-end example, and are downloaded assets reusable after account/API termination?
7. For IGDB, is there an approved public-client or desktop authentication model, and what commercial agreement covers local caches and image display?
